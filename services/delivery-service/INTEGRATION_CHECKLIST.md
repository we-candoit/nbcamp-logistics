# 배송 서비스 연동 후속 작업

## 요청자 헤더 규칙 및 감사 식별자 통일

작성일: 2026-10-17

### 현재 진행 기준: 기존 변경 최소화

- 기존 X-User-Name과 X-Role-Name 전달 및 감사 기록을 유지한다.
- createdBy / updatedBy / deletedBy는 기존 String·username 기준을 유지한다.
- 조회 권한 비교에는 사용자 PK UUID가 필요하므로 X-User-Id를 추가하는 방향으로 진행한다. 실제 헤더 전달은 Gateway·호출 서비스와 확인한다.
- UUID가 필요한 조회에서 헤더 누락·잘못된 형식은 허용하지 않는다. 기존 생성·취소·삭제에 X-User-Id를 일괄 필수로 요구하지 않는다.
- 주문자 소유권 확인 API 계약은 별도 확인이 필요하다.

### 팀 합의 후 수행할 작업

- [ ] 요청자 헤더 이름·타입·적용 범위·역할값을 팀 공통 규칙으로 확정한다.
- [ ] Gateway 및 서비스 간 호출에서 검증된 원 요청자 정보가 유지되는지 확인한다.
- [ ] 감사 식별자를 username으로 유지할지 사용자 UUID로 전환할지 합의한다.
- [ ] UUID로 전환할 경우 감사 필드·DB 컬럼·AuditorAware·삭제 메서드·테스트·문서를 함께 변경한다.
- [ ] 기존 username 감사 데이터를 보존·변환하는 정책을 정한다. username은 UUID로 직접 형변환할 수 없다.
- [ ] X-User-Name을 제거하기 전에 이를 사용하는 감사 코드와 호출자가 모두 전환됐는지 확인한다.
- [ ] 내부 API 호출자 인증과 외부 사용자 헤더 위조 방지 규칙을 확인한다. 헤더 존재 검사는 인증 자체가 아니다.

### 작업 중 리마인드할 시점

조회 인가 구현, Gateway·주문 서비스 연동, 감사 코드 변경, 관련 PR 작성 시 위 후속 작업을 다시 확인한다. 팀 합의 전에는 X-User-Name 제거 또는 감사 필드 UUID 전환을 임의로 진행하지 않는다.

## 주문 서비스 실행 및 주문자 상세 조회 연동 검증

기록일: 2026-10-18. 사용자 요청으로 실행 환경 설정과 실제 연동 테스트를 보류한다. 아래 항목은 미완료이며 서비스 실행·설정 변경을 수행했다는 뜻이 아니다.

- [ ] 주문 담당자에게 GET /api/orders/{id}가 구현된 브랜치·커밋을 확인한다. 2026-10-18 로컬 코드 확인 당시 해당 조회 컨트롤러를 찾지 못했다.
- [ ] 실제 응답의 orderId·orderUserId 및 조회 권한·오류 응답 계약을 확인한다.
- [ ] X-User-Id / X-User-Name / X-Role-Name 전달을 실제 주문 코드와 대조한다. 현재 배송 Client는 세 헤더 전달을 가정한다.
- [ ] 주문 서비스를 Java 21로 기동할 실행 구성과 주문용 환경변수를 준비한다.
- [ ] 주문의 현재 ddl-auto: create 설정을 확인하고 기존 데이터를 보존할 실행 설정으로 조정한다. 기존 주문 데이터를 삭제·재생성하는 방식으로 연동을 준비하지 않는다.
- [ ] 실행 방식에 맞는 DB 주소·포트·스키마와 주문 서비스 포트를 확인한다. IntelliJ 실행에서는 Docker 내부 호스트명과 localhost를 구분한다.
- [ ] 배송에서 주문에 접속할 방식을 선택한다: Eureka 사용 또는 로컬 Feign URL 직접 지정. 현재 배송 local 프로필은 Eureka가 비활성이다.
- [ ] 로컬 직접 연결을 선택하면 주문 localhost:8083, 배송 localhost:8084 구성을 후보로 사용하고 실제 포트 충돌 여부를 확인한다. 이는 아직 적용하지 않은 제안이다.
- [ ] 실제 주문과 연결된 배송, 주문자 UUID·username을 준비하고 주문 상세 API 단독 호출을 검증한다.
- [ ] 배송·경로 담당자가 아닌 본인 주문자가 배송을 조회하면 200인지 확인한다.
- [ ] 타 주문자는 404, 주문 서비스 장애·불완전 응답 등으로 소유권을 확인할 수 없으면 조회를 허용하지 않고 정의한 오류를 반환하는지 확인한다.

상세 조회 PR 작성 및 통합 테스트 재개 시 실제 주문 서비스 연동 검증이 보류되어 있음을 다시 명시한다. MASTER·담당자 로컬 조회 검증만으로 주문자 분기까지 통합 검증됐다고 표시하지 않는다.
